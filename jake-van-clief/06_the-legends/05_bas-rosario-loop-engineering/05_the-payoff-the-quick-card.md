## Summary

The payoff post pulls the three classes together, observes that the model never changed between attempts, and attributes all improvement to what the human wrote: checks, ending and checkpoint placement. It assembles one complete written loop as a single paragraph, then explains why this is only rung four: real work is many loops landing on one desk, which is the subject of the next series. It ends with a quick card for saving.

## Core concepts

- **Quality lives in the circuit, not the model:** the identical model produces better results when it is judged against written criteria than when it is judged by feel.
- **A loop is a paragraph of English:** every sentence maps to a class (ask, checks, again-rule and carry, budget, fixed target, handback, single question, gate), and only the last two need the human.
- **One loop is not a week:** real work chains loops (research feeding refinement) and several workstreams, which is a different discipline (orchestrating many workers with one person placing gates).

## Tools, settings and resources

## Apply to icm-workshop

- **Adopt as a review aid, not copied text.** When scaffolding a stage, run the card's five areas as questions against the draft contract: has it named checks, an ending, guards, and a single human placement?
- **Never build an orchestrator:** the payoff's "many loops, one desk" is exactly where Bas heads toward orchestration; the C3 desk should be the one desk where outputs land, with Jamie as the person placing gates, not a coordinating script.
