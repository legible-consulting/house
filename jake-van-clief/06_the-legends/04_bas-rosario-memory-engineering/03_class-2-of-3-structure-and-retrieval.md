# Class 2 of 3: Structure and retrieval

*THE LEGENDS › 4. Bas Rosario – Memory Engineering · Author: Bas Rosario · Source: text lesson*

## Summary

Bas argues that a memory only earns the name if the model actually has it in view when it is needed, which takes two steps: being loaded, and being found inside what was loaded. A flat, chronological file of true lines can still fail because the useful line sits where it will be skimmed. He says a memory that cannot be retrieved does more harm than having none, because it creates false confidence and stops you from checking. He demonstrates by reshaping a fourteen-line file into a short always-loaded section plus a separate drawer file, and ends with a method for testing retrieval in a fresh session.

## Core concepts

- **Two halves of remembering:** loaded (covered by the context series) and found. The second is rarely designed because it feels automatic; models attend to long lists unevenly, much like a person skimming terms and conditions.
- **Known gap versus unknown gap:** an absent fact makes you supply it; an unreachable fact makes you believe it is handled, so errors slip through unchecked.
- **Group by need, not by time:** chronological order is a diary; grouping by when a line is needed is a memory.
- **Headings are triggers:** a heading named for the situation that calls for it is how the line gets found.
- **Always-loaded versus drawer:** keep the loaded part small, move lines needed only for specific cases into their own file, and leave one pointer line saying when to open it. This is selective loading in ICM terms.
- **One fact, one place:** contradictory duplicates leave the model picking one at random.

## Frameworks and methods

1. Group by when needed and name each group by its trigger.
2. Order by cost of forgetting, with the most-burning line first.
3. Split rarely needed material into separate files with a pointer.
4. Test retrieval by opening a fresh window with the room loaded and asking the model what it knows about a given item before giving it any task.

Homework: re-sort lines you retyped despite their being in the file (retrieval failures, not memory failures), then test three lines in a fresh window.
