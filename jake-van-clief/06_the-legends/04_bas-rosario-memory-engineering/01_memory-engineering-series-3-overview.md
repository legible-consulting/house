# MEMORY ENGINEERING Series 3 Overview

*THE LEGENDS › 4. Bas Rosario – Memory Engineering · Author: Bas Rosario · Source: text lesson*

## Summary

Bas opens the third rung with the line that context is what the model sees this turn, while memory is what survives between turns. He argues the work changes character here: from writing instructions to designing a system that decides what is kept, where, and for how long. A renamed product term that the model keeps getting wrong shows memory engineering at its smallest, a single line written into the room's file. He warns that saving everything is the obvious trap, and previews three classes on selection, structure and retrieval, and decay, conflict and correction.

## Core concepts

- **Context versus memory:** context is the current turn; memory is what outlives the window, which means deciding what gets kept, where and for how long.
- **Corrections last as long as their window:** without a durable home, the same fix must be explained repeatedly.
- **Three benefits:** continuity for the model, the end of re-explaining for the learner, and, most importantly, memory as the precondition for delegation; handing work to something that forgets does not work.
- **Storage is not memory, memory is selection:** saving everything is cheap now and costly later, because each item must be found, trusted and loaded every time.
- **Pace:** Bas says he will go more slowly here because most learners stop on this rung, having never been asked to describe what should persist.

## Frameworks and methods

1. Class 1, what deserves to persist: durable versus disposable, plus a test every kept item must pass.
2. Class 2, structure and retrieval: how organisation decides whether a memory can be found; an unreachable memory is worse than none because it creates false confidence.
3. Class 3, decay, conflict and correction: updating rather than accumulating when kept facts go stale or disagree.
4. Entry task: list three things you re-explain every time, not thirty.

## Claims and evidence

- Most people stop at this rung because nothing prompts them to design persistence — Bas's observation — unverified.
- Memory is the precondition for delegation and for the later loop and graph rungs — argued by reasoning.

## Apply to icm-workshop

- **Adopt** the framing that memory engineering means choosing what survives: it is the design question behind C2, where each client folder keeps the relationship's facts for the whole life from prospect to after-handover. What belongs in the folder record and what is merely a session story needs an explicit rule.
- **Adopt** "memory precondition for delegation" as a justification for C2 and C3: the desk's morning glance and Friday review only work if the folders hold current, trustworthy state.
- **Reject** a save-everything approach (transcripts, full chat logs) in client folders; keep decisions and facts, not the story of reaching them.
- Entry task idea: list three facts Jamie re-explains in every fresh session and use that as the first seed of the shared core (C1).
