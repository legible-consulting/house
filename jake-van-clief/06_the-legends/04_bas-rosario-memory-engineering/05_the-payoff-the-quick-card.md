# The payoff: The quick card

*THE LEGENDS › 4. Bas Rosario – Memory Engineering · Author: Bas Rosario · Source: text lesson*

## Summary

The payoff shows that the whole memory series reduces to a small file, a drawer file and a calendar entry, with no system involved. Bas gathers the three classes (selection, retrieval, keeping it true) and lays out how the customer-update memory looks at the end. He then marks the limit of rung three: every check so far was you, and memory made delegation possible without making it safe. A system that checks its own work is the subject of the loop series.

## Core concepts

- **Three moves, one file:** select by four ordered questions, shape the file so lines are found, and keep it true through in-place correction, dated lines, a disagreement rule and a scheduled review.
- **The finished memory in outline:** an always-read section of about seven lines (changed names, banned words, length, send day with its source and an expected-to-change note, release status, a pointer to a customer file, and a stop-on-conflict rule), a drawer file of per-customer notes, and a review line for the owner.
- **Automation is the same discipline run by a machine:** every memory system performs selection, shaping and correction; here you did it by hand.
- **Why it is only rung three:** you were the checker at every step. Nothing yet lets the model notice staleness, bad updates or conflicts without you.
- **Two named failures:** reachable-in-theory but never found, and present but never revisited.

## What the quick card covers and how to use it

The card has five parts: a keep-it filter (the four class-one questions with the rule of writing survivors as rules, facts or preferences), a find-it set of retrieval rules plus the fresh-window test, a keep-it-true set for correction, dating, conflicts and reviews, a short statement of the two failure modes, and one line on why memory matters for delegation. Use it as a review sheet when auditing an existing memory file: walk each line through the filter, check headings and pointers, then run the dating and review checks. The prompt to the learner is to run the first monthly review early and report which of "still true", "since when" or "says who" fails most (Bas predicts "since when").

## Claims and evidence

- A memory built this way stays right next quarter because its failures become noticeable — the author's reasoning from a constructed example; untested.

## Apply to icm-workshop

- **Adopt** the file-plus-drawer-plus-calendar pattern as the minimum viable C2: per-client status file read at start, per-module artefacts as the drawer, and the review date placed on the desk (C3's Friday review and monthly close), not in someone's head.
- **Adopt** the final limit as a design boundary: gates are human, so memory correctness remains Jamie's check until a drift or deadline sweep (one of the unattended runs the goals allow) reports stale lines.
