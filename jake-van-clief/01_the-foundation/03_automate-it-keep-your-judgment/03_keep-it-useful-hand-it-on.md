# 3.3 Keep It Useful and Hand It On

*The Foundation › Module 3: Automate It, Keep Your Judgment · Author: Jake Van Clief · Source: Skool video + text page · Length: ~3:45 (estimated from captions)*

## Summary

The closing lesson covers keeping a workspace alive and transferring it. Because AI makes clutter cheap, a week-one folder can decay into a swamp where conflicting versions mislead the model. Jake offers three checks (fresh-session test, one home per fact, clear things out) and treats the map as the handover document for people as much as for the AI. He ends with a bet that files and folders outlast any single model or vendor.

## Core concepts

- **The swamp:** drafts, versions and summaries of summaries accumulate until the AI finds several prices and picks a stale one.
- **Archive with a one-line rule:** old work goes in an archive the map marks as never to be read.
- **Fresh-session test:** a new session must correctly say what the folder is, what is in progress and what is next; failure means the map is out of date.
- **One home per fact:** prices, rules and skills each live in one place; fix the skill file and every job picks it up.
- **Delete freely:** files are cheap to regenerate; leave originals, sources and others' material untouched, with Manual mode as a guard.
- **Map as onboarding:** the same file orients a new person; the test is whether you could do the work if the AI were switched off.

## Frameworks and methods

Handover options: hand over a copy (zip or shared drive, good for templates) or work in one shared place (synced drive or Git, which needs agreement on who changes what). Access is a permissions question the folder does not settle.

## Claims and evidence

- Folders have survived every platform shift since the 1960s and 70s Unix era, so they are the safe bet — historical argument plus opinion; the Ritchie and Thompson paper is the optional reading.
- Swapping models means re-pointing at the same folder and maybe renaming the map file — stated as expectation, not demonstrated.
