# 2.2 Design Your Folder

*The Foundation › Module 2: Build It Around Your Work · Author: Jake Van Clief · Source: Skool video + text page · Length: ~5:00 (estimated from captions)*

## Summary

Turns the outcome from 2.1 into a workspace. Three real shapes are compared (stages, records, a self-maintained wiki), all derived from the same method, ICM. The learner lists jobs with what each reads and makes, separates method, facts, work and outputs, labels each file as instructions, state or both, writes a short routing map, and tests with a real request. A free skill, ICM Architect, can draft the structure.

## Core concepts

- **Shape follows work:** stage folders for pipelines, record folders for per-client work, and a wiki with raw sources apart from AI-written linked pages (an idea credited to Karpathy).
- **ICM as method, not template:** the term describes the way of thinking that produces the folder; his folder will not look like yours.
- **Method, facts, work, outputs:** method carries across clients, facts stay with one; the same split as skill versus project.
- **Instructions-runner-state lens:** a program is instructions, something running them and state it reads and changes. The model is the runner; the other two are the user's to write. A file that is neither instructions nor state is the first suspect.
- **Short routing map:** the commonest mistake he sees is a giant map that puts the whole drawer back on the desk.
- **Smallest version first:** add rooms only when the work asks.

## Frameworks and methods

1. List the jobs toward the outcome; for each, note reads and makes.
2. Split files into method, facts, work, outputs.
3. Label each file instruction, state or both.
4. Write the map: contents, destinations, naming, routing table.
5. Test in a new session; if it reads everything, tighten the vague row.
