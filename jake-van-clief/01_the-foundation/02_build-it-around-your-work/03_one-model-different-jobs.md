# 2.3 One Model, Different Jobs

*The Foundation › Module 2: Build It Around Your Work · Author: Jake Van Clief · Source: Skool video + text page · Length: ~3:30 (estimated from captions)*

## Summary

The lesson argues that a role is created by what the model reads, not by naming an agent. A single folder map can route requests such as make a video, write a short, schedule a finished one or fix the kit, each to different files with the same model. It then separates what belongs to the model (reading a situation and choosing) from what belongs to tools and code (doing exact actions), and finishes with the few cases where several agents are justified and their costs.

## Core concepts

- **Role from reading:** a writing, scheduling or research agent is usually just written instructions per job plus a map that routes to them; a label adds nothing.
- **Model chooses, tools do:** in his folder the model selects what to post, a scheduling connection posts, and rendering is a fixed command.
- **When multiple agents pay off:** lots of independent parallel work (researching ten companies), a job large enough to bury the desk, or something live needing constant watching.
- **Cheapest multi-agent is a second session** on the same folder; sub-agents return only an answer so the main desk stays clean.
- **Costs:** more tokens, more waiting, more handoff failure points; start with one and split only for a named job.

## Frameworks and methods

Test: give the folder two unlike jobs back to back and watch the files each opens. Then find one job that could run independently alongside others.
