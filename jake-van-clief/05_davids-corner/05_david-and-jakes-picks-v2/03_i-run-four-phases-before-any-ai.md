# I run four phases before any AI builds anything.

*David's Corner › David and Jake's Picks V2 · Author: Ari (member; post summarised by David's Corner) · Source: text lesson (links to original post)*

## Summary

Ari's method puts four phases before any build: brainstorm, plan, a hand-off document, and dispatch. The page recommends it when ambiguity keeps producing the wrong thing. The exercise uses a fictional event page: list two approaches, choose one, write a hand-off with inputs and exclusions, then request one small implementation step. Before dispatch, name a visible acceptance check and compare afterwards. It notes planning reduces avoidable ambiguity but does not guarantee a correct first pass.

## Core concepts

- **Hand-off document as the contract** between planning and building.
- **Acceptance check named before dispatch.**
- **Exclusions stated**, not just inputs.

## Frameworks and methods

Four sequential phases: brainstorm, plan, hand-off document, dispatch. Detail is in the original post, not the page.

## Apply to icm-workshop

- **D2 SDLC:** the hand-off document resembles a ticket-to-build stage contract; adapt as the planning stage's output, with the acceptance check as the UAT criterion the client signs.
- Boundary: dispatch must remain a human act; a session does not advance a stage on its own.
