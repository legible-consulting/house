# Stop Prompting. Start Defining Outcomes.

*David's Corner › David and Jake's Picks V2 · Author: Ari (member; post summarised by David's Corner) · Source: text lesson (links to original post)*

## Summary

Another Ari post, moving from an open-ended request to a brief built around an inspectable result. The exercise rewrites a vague request ("help me with my newsletter") into a brief with audience, supplied sources, one deliverable, length, tone and review criteria, and asks the assistant to list missing information before drafting. The test is whether another person can tell if the result meets the brief. The page cautions that well-defined inputs are useful, yet the model's ability, how good the sources are, and human review all continue to count.

## Core concepts

- **Outcome brief over prompt:** audience, sources, deliverable, constraints, criteria.
- **Gaps first:** ask for missing information before drafting.
- **Third-party check:** someone else can judge the result.

## Apply to icm-workshop

- Adopt as the shape of S3 proposal and D1 kickoff inputs: a result someone else can verify, matching the goal that a client can say yes without a second call.
- Same pattern as the measurable-outcome note earlier in this module; one home for the brief template in C1, not copies in each module.
