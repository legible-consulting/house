# The 5 Levels of AI Mastery

*David's Corner › Curtis Hays - Systems Worth Amplifying · Author: Curtis Hays · Source: text lesson*

## Summary

Curtis lays out a five-rung ladder describing how people progress from typing into a chat window to running coordinated agents, and argues most users sit on rung one without knowing the rest exist. Each rung removes a specific kind of friction: forgetting, re-explaining, file shuffling, manual routing, and finally your own presence. His practical advice is to locate where you really are, climb one rung at a time, and spend real time on the second rung before reaching for anything fancier. He also warns that the top rung costs money and removes the human check that keeps work pointed at something true.

## Core concepts

- **Amnesia as the root problem at level one:** a chat has no memory across sessions, so every new conversation re-trains the assistant. People compensate by never closing one long thread, which is fragile.
- **Persistent context as the biggest early gain:** project-style features (projects in ChatGPT and Claude, gems in Gemini) let you write role, objective, source files and voice rules once, so later chats start with natural language instead of a long setup prompt.
- **Loading trusted expertise:** a third party's framework can be placed in a project so the assistant applies it routinely rather than answering generically.
- **Tool access changes the nature of the work:** once the assistant can read and write local files and call business tools, the cost of moving information between you and your systems collapses.
- **Bottleneck of the router:** you can own many agents and still be the one manually deciding which to ask; orchestration is what fixes that.
- **Selective automation:** most people need to be solid at the fourth rung and choose which workflows deserve full automation.

## Frameworks and methods

1. **Level 1, chat with amnesia:** one-off conversations; learn prompting, but expect to retype context.
2. **Level 2, assistant with memory:** build a single project for the work you do most; define persona, constraints, examples.
3. **Level 3, assistant with file and tool access:** point a desktop tool at a folder; delegate filing, spreadsheet edits and CRM entry, then review.
4. **Level 4, orchestrator with specialists:** one router agent hands requests to role-specific agents, all kept as plain text files in a folder tree.
5. **Level 5, unattended factory:** agents run overnight and you review output in the morning; weigh token cost and the loss of a human in the loop.

Where to start: find your honest level; if you are in one long chat, build one project, not ten; if projects work, move to file access; if you feel the ceiling at level three, start sketching a team.

## Claims and evidence

- Most AI users are on level one — author's impression from conversations, no data.
- A user kept one chat running for thirteen months — anecdote.
- An assistant created three CRM deals, tasks and notes from a spoken call summary — author's own workflow, unverified.
- Overnight agent runs can burn hundreds of dollars — stated as a general risk, no figures from a specific run.
- Author says he is not at level five and has little need to be — useful caveat; the top level is described from second-hand knowledge.

## Apply to icm-workshop

- **O4 training and coaching:** the ladder is a ready-made diagnostic for the first ten minutes of a workshop: which rung is the attendee on? Adopt it as a placement exercise, with a client leaving at rung four (a folder tree) as the target for "leave with their own factory".
- **Boundaries:** level five conflicts with the goals' "gates are human" and "never build an orchestrator" rules. Curtis's router agent is realised in ICM as folders and stage contracts, not as a running agent, so adapt the rung-four idea (specialists as files, routing by structure) and reject the unattended rung except for the three sanctioned unattended sweeps.
- **C1 shared core, every module starts cold:** the intern-with-amnesia image is exactly why each module must carry its context in its own folder. Use it as the plain-language justification.
- **D2 SDLC:** the review-in-the-morning model suggests unattended runs should only produce lines for the next morning's glance (C3).
