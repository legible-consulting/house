# My AI Workflow Evolution

*David's Corner › Learning for Everyone · Author: David's Corner (author not stated; one contributor's field note) · Source: text lesson*

## Summary

A history of one contributor's layers while supporting nonprofit work: one-off prompting, open-source tools on free credits, specification-first tools, ICM folders, then memory experiments ending in a Hermes plus Cognee setup. The message is to add a layer only when you can name the capability the simpler setup lacks, and to test each layer on the same fictional task. It notes that retrieval can be keyword, vector or graph, that a graph does not make relationships correct, and that agent-created skills and memories still need review.

## Core concepts

- **Name the missing capability first** before adding retrieval or orchestration.
- **Costs are not only credits:** hosting, model, integration and maintenance count; free-credit eligibility needs fresh checks.
- **Short loaded instructions:** keep always-loaded files inspectable and push detail into separate files. The 150-line figure is a personal heuristic.
- **Graph is representation, not reasoning.**

## Tools, settings and resources

- Kiro, BMAD Method, Open Brain, ClaudeBot, ZeroClaw, Hermes, Cognee — named stops on the path; none vetted here.

## Apply to icm-workshop

- Supports "start with folders, add machinery only for a named gap": for a memory layer, the goals' boundary "every module starts cold" argues for files over a retrieval stack.
- O1: a verdict record for Hermes or Cognee would need a dated adopt, watch or decline; this page alone is anecdote.
