# Folders, Obsidian, and Workflow Execution

*David's Corner › Learning for Everyone · Author: David's Corner (author not stated; field note) · Source: text lesson*

## Summary

A field note arguing that plain files are the right default for an ICM workspace. Numbered stage folders make stages visible, but they do not execute anything: instructions tell an assistant what to read and produce, and a person, script or configured agent still has to do the steps. The page compares interfaces (file manager plus editor, a development editor, Obsidian, a dashboard) and says to add a dashboard only when a real navigation problem remains.

## Core concepts

- **Folders do not run anything:** structure documents order; execution comes from someone or something else.
- **Files first, app optional:** a workspace should still make sense when reopened in a different editor.
- **Obsidian as viewer:** notes are local Markdown, but plugins and special syntax can reduce portability.
- **Dashboard on demand:** only when navigation is a demonstrated pain.

## Apply to icm-workshop

- Confirms the boundary "never build an orchestrator": folders and contracts are the pipeline. Keep as a one-line why in the repo's rules.
- Relevant to C3: the dashboard exists for salesmen and clients, not as the pipeline's engine; folders stay the record. Add a portability test for D4: a module opens cold in any editor.
